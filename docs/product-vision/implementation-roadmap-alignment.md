# Implementation Roadmap Alignment

**Статус:** **Proposed.** Сопоставление канонических этапов Production Plan v2.1 (PS-0…PS-14, ADG) и релизных вех (M0…M8, M2-T/M2/M3 — все Proposed) с шестью **предполагаемыми продуктовыми срезами**. Срезы — разметка для планирования, **не** новая утверждённая последовательность и **не** новая нумерация этапов. Ничего не авторизует старт PS-1.
**Дата:** 2026-11-09. Ссылки: `CPR-/AI-/OPN-` — `cube-product-vision.md`; `VP-` — `cube-owner-decision-register.md`; `R-n` — `production-plan-alignment-report.md` §4.

## 0. Принципы

1. Цель — как можно раньше получить работающую игру: каждый срез завершается тем, что игрок (или тестер) делает руками; прогресс не измеряется числом задач (`GAME_TRACK_ROADMAP.md` §7).
2. Канонические этапы не переименовываются. Срез ссылается на PS-n и M-n.
3. Критерии приёмки и тесты ниже — **предложения**; численные пороги производительности не выдумываются (измерить → владелец задаёт порог).
4. «Сознательно не реализуется» — конкретный список, чтобы срезы не росли сами по себе.
5. Параллельность — только по зависимостям ADG; ADG содержит известные дефекты D-01/D-02 (патч Proposed), и «параллельно» здесь означает «не имеют общих зависимостей по задачам», а не разрешение мержить мимо ворот.

## 2. PSL-1 Архитектурный фундамент

* **Минимальный scope:** закрыть PS-0 (G0: 8 задач, 15 решений GOV-01, registry, CI, archcheck); PS-1 Core (P0-alpha); PS-2 Processing (Provisional); PS-3 контракты Editing API; PS-4 Orchestration; voxel-бэкенд; тестовая инфраструктура.
* **Новое от OC-2026-11-09 внутри PSL-1 (минимум):** в уже существующие решения вписать M-1, M-2, M-3 (три короткие фразы в D-C, ACR-004 A/D, D-T). Контентные контракты (CR-01…CR-05) пишутся как Draft — реализация не нужна до PSL-2.
* **Зависимости:** ODM-10 (механизм подтверждения), 15 решений GOV-01, ST-1/ST-2, ветка для базы (GOV-01 №15), CI (GOV-05/06), владельцы Core/Integration/Agent I (GOV-03).
* **Критерии приёмки (предложение):** PS-1 exit criteria (plan §15) — без изменений; плюс «никакой код Core не содержит слова `namespace`, `pack`, имён материалов» (archcheck-правило AI-01); P0-alpha формулирует `MaterialIndex` как непрозрачный.
* **Тесты:** property-тесты CommitBatch, compile-fail тесты capability handles, commit-log completeness (plan §6), архитектурные правила XT-01/02, детерминизм; **не** запущены в рамках этого анализа.
* **Риски:** G0 не сдвигается без владельца (ODM-10…); спайк-код мигрирует в production «по инерции» (AOD-18/24); ширина ключа и `u16` зашьются без OPN-01.
* **Параллельно:** написание Draft CR-01…05 и WP-01-ревизии (документация) не пересекается с Core-задачами; GM-02 (entity spike) и SPK-PERS — по разрешению владельца (ODM-12), вне production-ветки.
* **Сознательно не делается:** crate `cube-content` как код; любой пакетный загрузчик; микровоксели (только `level` в ключе, как задумано в PC-1); физика; игровые правила.

## 3. PSL-2 Играбельный процедурный мир (M2-T)

* **Минимальный scope:** создание мира по seed; детерминированная генерация (один биом, затем 2); ходьба по терейну с коллизиями (kinematic); меш вокселей; разрушение/установка через Editing API; сохранение и перезагрузка; embedded runtime с in-process transport (AOD-22; ODM-16 вариант a).
* **Новое от OC-2026-11-09:**
  * встроенный контент загружается через минимальный слой контента: пакет `cube`, идентичность `cube:stone` и т. п., таблица `IdMap` — **для одного пакета**; встроенные материалы не зашиты как числа в генераторе/клиенте;
  * заголовок сохранения несёт `GameVersion`, `PackSet`, `IdMaps` (допустим экспериментальный формат TC-08, но поля заложены — дёшево);
  * запись игрока (позиция) — отдельная запись (VP-07).
* **Зависимости:** PSL-1; D-K/ODM-11 (границы мира, `VoxelPos`); PS-11A (чистый генератор) и 11B (materialiser); PS-10 в форме base+snapshot (T-08); PS-12-срез; SRV-01.
* **Критерии приёмки (предложение; AC-01…AC-16 из `M2T_ACCEPTANCE_CRITERIA.md` без изменений), плюс:**
  * AC-C1: мир, созданный с пакетом `cube` версии X, загружается; при подмене версии на несовместимую — обычная загрузка отказывает, файл побайтно не изменён;
  * AC-C2: синтетическая фикстура-пакет добавляет материал; мир с этим материалом без фикстуры не загружается обычным путём, в режиме восстановления показывается заглушка и после сохранения payload неизвестного материала побайтно сохранён;
  * AC-C3: повторная регистрация полного id даёт диагностическую ошибку в журнале логов, не crash.
* **Тесты:** детерминизм хэшей чанков (AC-03); round-trip сохранения; тесты AC-C1…C3; тест «определения создаются только загрузчиком» (VP-12); на целевой платформе — измерения, не пороги.
* **Риски:** время (PS-11, PS-10, PS-12, PS-13-срез идут как цепочка); ODM-02/03 (Provisional PC-1 и Processing); отсутствие владельцев (ODM-04); соблазн расширить контентный слой до полноценного мод-загрузчика.
* **Параллельно:** WGEN (pure generator) ∥ PS-10 base+snapshot ∥ клиентская оболочка; CONT-задачи (M-4) ∥ всё остальное, пока они не трогают Core и persistence-контракты.
* **Сознательно не делается:** загрузка сторонних пакетов; режим recovery с заменами/миграциями; схема версий диапазонов (достаточно точной версии `cube`); wire protocol и внешний транспорт; подвижные конструкции; фоновая симуляция.

## 4. PSL-3 Редактирование и микровоксели

* **Минимальный scope:** Undo/Redo (PS-7); область (box) и заливка; инструменты проектирования минимального уровня (копирование/вставка, симметрия — по решению); **микровокселы** в минимальном режиме (VP-10): фиксированные уровни, клетка либо крупная, либо разбита; без resampling-перехода; чертёж как asset с палитрой стабильных id (AI-12); вставка чертежа — одна операция.
* **Зависимости:** PSL-2; решения OPN-07 (объём PS-5/6), OPN-08 (уровни); PS-7 History; PS-8 только если чертёж/композит требует; D-K/D-T/D-C зафиксированы.
* **Критерии приёмки (предложение):** игрок ставит и ломает вокселы на двух уровнях детализации в одной постройке; сохранение/перезагрузка возвращают те же вокселы обоих уровней; Undo/Redo возвращают состояние бит-в-бит (критерий E-серии «apply(inverse(delta)) restores bit-exact»); чертёж, сохранённый в мире A, вставляется в мир B с другой id-картой и теми же материалами; для материала, отсутствующего в B, вставка отказывает с диагностикой (не молча заменяет).
* **Тесты:** property-тесты рефайнмента (ставит/снимает → исходное); тесты границы уровней на меше (визуальный регресс на одном наборе сцен); round-trip чертежа между двумя id-картами; undo-bit-exactness; нагрузочный замер крупной вставки (измерение, пороги — владелец).
* **Риски:** PS-9 (полный Resampling) может понадобиться раньше; шов между уровнями на меше выглядит плохо (приёмка визуальная); C-12 открыт; Provisional PC-1; цена крупных операций (AI-10).
* **Параллельно:** History ∥ micro-режим ∥ формат чертежа; зависят от разных crate.
* **Сознательно не делается:** SDF/Mesh-бэкенды и Sculpt/Boolean (если OPN-07 решён как «после First Playable»); гладкий resampling; права территорий; серверная история между сессиями; подвижные конструкции; динамическая физика построек.

## 5. PSL-4 Базовый игровой контент и RPG

* **Минимальный scope:** модуль `game-rules` (только после `GM-02` и решения ODM-05): персонаж, бой (1 hostile + 1 passive существо), лут, инвентарь, один слот экипировки со статами, смерть/возрождение, HUD (FIRST_PLAYABLE_SCOPE). Определения (предметы, существа, статы) — данные пакета `cube`; правила прогрессии (уровни и очки) — данные; формулы убывающей отдачи — параметры, не код.
* **Новое от OC-2026-11-09:** не нужны классы/мультикласс/исследования/мастерство (CPR-RPG-01…07 — M4); достаточно, чтобы структура данных персонажа не исключала их (запись персонажа отдельная, VP-07; числовые поля — решение OPN-01 для ширины «бесконечного роста»).
* **Зависимости:** PSL-2 (мир, сервер-runtime), `GM-02` (entity-модель, REF-13), владельцы gameplay/content/art (ODM-04), ODM-05.
* **Критерии приёмки:** FPS-01…FPS-17 (`FIRST_PLAYABLE_SCOPE.md`; Proposed) без изменений; плюс «все определения предметов/существ загружены из пакета `cube`, а не зашиты в коде» (проверка тестом AC-C-подобного вида).
* **Тесты:** сценарные (бой → дроп → экипировка → стат), детерминизм боевых расчётов при одинаковом seed ввода (если принято), сохранение инвентаря/экипировки, тест «нет определений вне загрузчика».
* **Риски:** нет владельца gameplay; entity-модель не выбрана; «игра» без арта; бой перегружается механиками.
* **Параллельно:** контент-данные ∥ сценарии боя ∥ HUD после стабилизации интерфейса World Operations (TGAP-03a).
* **Сознательно не делается:** мультиклассовость, исследования, мастерство, динамическое масштабирование, торговля, групповые награды, механизмы кроме простых дверей/рычагов, программируемые устройства, энергосети, мод-API.

## 6. PSL-5 Сетевой кооператив (M4)

* **Минимальный scope:** dedicated server (тот же runtime), внешний транспорт (OAM-05 spike), сессии, авторизация, репликация (интерес-менеджмент), совместное строительство через `expected`-конфликты, простые права (владелец/доступ; полноценные территории — позже), отдельная запись персонажа на сервер.
* **Зависимости:** PSL-2…PSL-4; OAM-05; PS-13; владелец Networking/Server (ODM-04); модель аккаунтов (не решена — M4 планирование).
* **Критерии приёмки (предложение):** два клиента строят в одном регионе, при конфликте один получает определённый отказ с возвращённым состоянием; отключение/переподключение не теряет изменений (журнал); один набор conformance-тестов проходит на in-process и внешнем транспорте (AOD-22 (10)); клиент не может записывать авторитетное состояние.
* **Тесты:** conformance SR-09; тест двойной записи; fault injection на журнале; нагрузочный замер (числа — измерить).
* **Риски:** выбор транспорта; mobile (AOD-08/11: физическое устройство нужно, эмулятор не доказывает); атомарная группа журнала (VP-08) — если не заложена в формат, ломает формат.
* **Параллельно:** транспорт ∥ репликация ∥ права; при условии стабильных интерфейсов PS-13.
* **Сознательно не делается:** рынки, аукционы, обмен между серверами, общий прогресс доверенных серверов, моды в мультиплеере, 500 игроков и распределение по регионам (M6).

## 7. PSL-6 Первый законченный RPG gameplay loop

* **Минимальный scope:** срез PSL-2…PSL-5 в виде связной игры на несколько часов: несколько окружений, типов существ, предметов, простая прогрессия с выбором билда (горизонтальный рост — начало), строительство и чертежи, сохранение/возврат, кооператив на dedicated.
* **Зависимости:** контент (арт/аудио/дизайн), GDD/TDD (BLK-06), владельцы, M3-решения (ODM-15).
* **Критерии приёмки:** `VERTICAL_SLICE_SCOPE.md` (Proposed) и player-facing доказательства (`GAME_TRACK_ROADMAP.md` §7): «outside tester plays without explanation», повторяемость цикла по собственному выбору.
* **Тесты:** playtest-ноты и записанные демонстрации, регресс сохранений (мир, сохранённый предыдущей сборкой, загружается; несовместимость даёт блок, не потерю), утечки/стабильность — измерения.
* **Риски:** объём контента; «бесконечное проектирование» — каждое требование обязательно привязывается к PSL.
* **Параллельно:** контент ∥ доводка боя ∥ интеграционные тесты.
* **Сознательно не делается (до явного решения):** DF-01…DF-18 из `cube-product-vision.md` §4: сторонние моды и SDK, инженерия/автоматизация, торговля/экономика, динамическая физика построек, подвижные конструкции, фоновая симуляция регионов, мультиклассы целиком, перенос между серверами.
