# Provisional contract review: TC-01...TC-11 (proposed)

**Status:** **Proposed** / `PENDING_OWNER_DECISION` (ODM-07). Reviews the temporary contracts of `docs/archive/m2-delivery-review/M2_MINIMUM_CONTRACTS.md` against the Draft long-term contracts in `docs/api-contracts/` and the decisions in `docs/decisions/`. **The content of the Geometry Processing Specification and of the Voxel Architecture is unknown** (absent from the repository) and is not reconstructed; where a judgement would need it, the review says "unknown". A Provisional contract is not an approved architecture and does not become one by use; none is registered by this review.
**New:** TC-11 (World Operations interface) is added because the local authoritative runtime (`ODM-16`) needs a contract that the previous TC set did not contain.

## 1. Classification used

* **Implementation contract (IC):** what code in M2-T must conform to.
* **Compatibility boundary (CB):** what must exist as a type, trait or rule so that later work is additive, even if not implemented now.
* **Deferred full specification (DS):** the long-term document or contract that supersedes the temporary one.

## 4. Gaps in the previous TC set found by this review

1. TC-02 did not state the dense index order (hash-relevant). 2. TC-01 did not choose between the Draft's open alternatives (pin versus copy; per-brick versus per-region). 3. No contract named the **local authority interface** (added as TC-11). 4. TC-05 and TC-06 have **no** long-term counterpart at all, so they risk becoming permanent by default; their expiry triggers are therefore tied to concrete events. 5. TC-08 deviates from "the journal is the primary record" and must say so in its registry entry (it does, section 3 of the previous package; the register entry must repeat it).

## 5. Guard against silent permanence

Each registered TC carries: id, expiry trigger, owner entry, migration note, affected tasks; a CI check (once CI exists) fails when an expiry condition is met and the entry is still open; tests that depend on a Provisional contract are tagged `provisional`; no TC becomes Frozen without revalidation and the owner (plan 3.1). None of this is implemented.
