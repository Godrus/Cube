# M2 task graph (proposed)

**Status:** **Proposed.** A separate graph; the Authoritative Dependency Graph (ADG, [`docs/production/module-boundaries.md`](../../production/module-boundaries.md)) is **not modified** and no status of any ADG task or gate changes. Nothing here authorises work. Generated by `_build/m2_graph.py` (outside the repository) from the committed ADG at HEAD `362a124`; the tables below are generator output, not hand-edited.
**Companions:** [`M2_SCOPE_REVIEW.md`](M2_SCOPE_REVIEW.md) (what M2-T and M2 are), [`M2_OWNERSHIP_MATRIX.md`](M2_OWNERSHIP_MATRIX.md), [`M2_MINIMUM_CONTRACTS.md`](../../api-contracts/M2_MINIMUM_CONTRACTS.md), [`M2_DELIVERY_PLAN.md`](M2_DELIVERY_PLAN.md).

## 1. Rules used to build it

* **Ids.** Existing ADG ids are reused unchanged. New tasks use three prefixes that do not occur in the ADG: **`TGAP-`** (technology gap: needed by the loop, absent from the ADG), **`GM-`** (Game Track), **`XI-`** (cross-track integration). Decisions that block work are referenced as `GOV-nn` (existing) or `ODM-nn` (new owner decisions, [`OWNER_DECISIONS_REQUIRED.md`](OWNER_DECISIONS_REQUIRED.md)).
* **Milestone.** `Pre` = pre-implementation (decisions, governance closure, design, spikes); `M2-T` = Technical Playable; `M2` = First Playable; `Later` tasks are not in the graph.
* **Edges of existing tasks** are the ADG edges, restricted to this proposal: an edge to a task that is in the graph is kept; an edge to a gate `Gn` is replaced by the members of `Gn` that are in the graph and not later than the task's milestone; an edge to an external input or a decision task is kept as a blocking decision; an edge to a task that is not in the graph is dropped and listed in section 5 (never silently).
* **No artificial dependencies:** nothing in this graph depends on a full SDF or mesh backend, the greedy mesher, History, Composite, Resampling, tools, the dedicated host or the external transport. Lower layers never depend on gameplay tasks.
* `G0*` in a dependency column abbreviates the eight G0 tasks `GOV-01`...`GOV-06`, `TEST-01`, `XT-01`.
* The graph **assumes the owner accepts the temporary contracts of [`M2_MINIMUM_CONTRACTS.md`](../../api-contracts/M2_MINIMUM_CONTRACTS.md)** (Provisional status instead of waiting for two absent documents). Without that acceptance the ADG's external inputs apply (section 6).

## 6. If the owner does not accept temporary contracts

The ADG's external inputs apply: the Geometry Processing Specification (`EXT-GPS`, through `GOV-07` and gate G2) gates every production merge from `API-02` onward; the Voxel Architecture (`EXT-VA-RG1`) gates `CORE-12`/`ADP-01` and the persistence format `GOV-10`. In that case the graph above is unchanged in shape but every task after `PROC-05` waits for a document, and nothing in the repository says when it will exist. This is the largest schedule risk of the project and it is not an engineering risk.
